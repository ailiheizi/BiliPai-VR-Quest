# VR 交互体验设计（参考 YouTube VR 范式）

> 你实际体验 Wolvic 时列的痛点：视频播放控制难、不想用手柄想纯手势、激光点击不准、滚动/翻页不顺、输入文字麻烦。
> 这篇把 YouTube VR 的交互范式翻译成 BiliPai VR 的具体设计规则。

---

## 一、痛点 → 设计对策对照

| 你在 Wolvic 的痛点 | 根因 | VR 设计对策 |
| --- | --- | --- |
| 视频播放控制难 | 触屏小控件在 VR 里不可用 | 播放页全部改成**大按钮 + 大滑块**（见 §3） |
| 不想握手柄，想纯手势 | 网页/Wolvic 对手势支持差 | 依赖 Horizon OS 手部追踪：**手部射线 + 食指捏合(Pinch)** 就是点击；手柄可选 |
| 激光点击不准 | 小目标（卡片/链接）难瞄准 | 目标放大、加**吸附/磁吸**（射线接近时高亮放大）、选中态明显 |
| 滚动/翻页不顺 | 网页滚动条难抓 | 列表用**大卡片墙**，翻页用翻页式或轨道式，不用细滚动条 |
| 输入文字麻烦 | VR 键盘 + 触屏键盘都差 | **扫码登录**（B站支持）+ 语音搜索 + 减少打字 |

---

## 二、三大交互范式（照搬 YouTube VR）

### 1. 视频墙 / 内容墙（主页）
- 内容以 **大卡片** 排列，横向一排 2-3 张，或环绕式弧面
- 选择 = 射线/凝视指向 + 短暂停留或 Pinch，**不需要精细点击**
- 参考：YouTube VR 主界面的环绕视频墙

### 2. 影院大屏（播放页）
- 视频是**核心**，面板要大、可调节距离/曲率（`PanelRegistration` 的 `QuadLayerConfig`）
- 播放中控件**自动隐藏**，唤出时以**大控件浮层**出现
- 参考：YouTube VR 播放页 = 大屏 + 极简大控件 + 沉浸背景

### 3. 极简控制（所有控件）
- 按钮最小 **96px（约 2 倍手机）**，间距 ≥ 48dp
- 滑块（进度/音量）加粗加高，拖动区域大
- 每个可交互元素有**明显的 hover/选中态**（高亮 + 放大 + 轻微音效）

## 三、逐页面设计规则

### 3.1 主页 / 推荐流
- 手机版：竖屏密集列表
- VR 版：横排大卡片（封面 + 标题 + UP主），一排 2-3 张，翻页式滚动
- 顶部：搜索入口（大按钮）、登录状态

### 3.2 视频播放页（最高优先级改造）
- 布局：视频占面板 70%+，下方一条控制条
- 控件全部大按钮：
  - 播放/暂停（中央，点击整个大区域触发）
  - 进度条：整行大滑块，可点可拖，带预览缩略图
  - 音量 / 清晰度 / 倍速：右侧竖排大图标
  - 弹幕开关：大开关
- 全屏/退出：明确的大按钮
- 参考 `MediaPlayerSample/MRPanel.kt` 的面板结构

### 3.3 搜索
- 大搜索框 + VR 系统键盘（Horizon OS 自带）
- 语音搜索优先（B站搜索框支持语音）
- 热门搜索大词条直接点

### 3.4 登录
- 首推**扫码登录**（B站 App 扫头显内二维码）—— 完全不用打字，也顺便缓解"登录状态丢失"（扫码后会话保持）
- 手机号验证码登录为备选

### 3.5 弹幕 / 评论区
- 弹幕字号放大到 VR 舒适（面板内），速度可调
- 评论区折叠成"打开"按钮，避免满屏小字

## 四、输入与手部交互细节

### 4.1 手部追踪（纯手势，不用手柄）
- 手部射线：从手指出射线，指向即 hover
- Pinch（拇指+食指捏合）= 点击/确认
- 掌心菜单（系统级）：快速返回/退出
- 注意：Quest 2 手势精度 < Quest 3，目标要更大、吸附要更强

### 4.2 手柄（可选，双通道并存）
- 激光射线 + 扳机 = 点击
- 摇杆 = 滚动/翻页（替代触摸滚动）
- A/B 键 = 确认/返回

### 4.3 吸附与防误触
- 射线接近目标 30-50px 内自动放大高亮（磁吸）
- 选中后需确认动作（点击），避免悬停误触发

## 五、舒适度规则（防眩晕）

| 项 | 规则 |
| --- | --- |
| 面板距离 | 1.5m-2.5m 之间，可调 |
| 面板曲率 | 轻微内凹（电影院感），不要太弯 |
| 移动 | 固定面板（LOCAL_FLOOR 锚定），避免 UI 随头动 |
| 滚动 | 用翻页/轨道式滚动，避免持续长滚动 |
| 字号 | 最小 18px+，正文 24px+ |
| 帧率 | 目标 72fps+，Quest 2 硬件解码播放器够用 |
